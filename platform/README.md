# AI微课工坊 · 机构课程平台

## 1.2 机构、用户与组织架构

- **平台管理 → 机构管理**：创建机构、指定已注册负责人、编辑机构信息、停用和恢复机构。停用会关闭该机构公开课程和内部业务入口，保留历史数据。
- **平台管理 → 用户管理**：按姓名、邮箱、机构、账号状态查询；创建普通账号、修改姓名、停用和恢复账号，分配机构、部门、岗位及角色。系统生成随机初始密码，只在创建成功时展示一次；平台不会发送邮件。账号停用会立即注销已有会话。
- **机构管理 → 组织架构**：建立最多六级部门，调整上级和显示顺序；自动阻止循环层级、跨机构父级和同级重名。删除部门前必须移出全部成员、处理子部门和待接受邀请。
- **机构管理 → 机构成员**：添加已注册用户、生成指定邮箱的邀请、调整部门和岗位、管理机构内角色及状态。支持姓名、邮箱、岗位、角色、状态筛选，以及按部门包含下级的筛选；可查看并撤销邀请。
- **账户菜单 → 我的机构**：查看本人加入的机构、部门、岗位和角色，切换机构课程。

一个账号可以加入多个机构，在每个机构分配一个部门及独立角色。普通成员（`learner`）可以使用课程、规则组课、询价及已授权资源，不获得课程编辑或人员管理权限。部门关系不会继承管理权限。停用机构内成员不影响其他机构；平台停用账号影响全部机构。

机构负责人和平台管理员可以分配负责人。机构管理员不能授予或调整负责人角色。最后一位有效负责人不能被降级、停用成员资格或停用账号。平台管理员可管理机构和账号，但不会自动获得其他机构的课程编辑、报价和资源读取权限。

升级在启动时执行幂等迁移，新增部门、成员资料及邀请资料表；既有账号、密码、课程、方案、报价保持不变，旧成员显示为“未分配部门”，可随后安排归属。上线前应备份数据库与附件。部门不预置虚构组织名称。

新增验收：`python -m pytest platform/tests -q`；`node platform/tests/organizations.cjs` 验证创建部门、创建账号、分配与调动、多机构归属、邀请撤销、普通成员权限及移动端布局。

这是基于现有 AIGC 课程菜单构建的第一阶段完整业务系统，包含网页、服务器、数据库和部署配置。原 GitHub Pages 课程展示站继续独立保留；本系统需要 Python 后端，不能仅上传 GitHub Pages 后运行。

## 现在如何使用

本机地址：**http://127.0.0.1:8765**。

首次登录账号和随机密码位于 `platform/runtime/首次登录.txt`。账号初始为 `owner@local.test`，同时具有平台管理员和默认机构负责人权限。登录后在“设置”修改密码。初始化命令不会覆盖已有数据。

1. 打开“课程菜单”：已有 **47 门课程、75 小时内容**，F/T/P/B 分色，支持搜索、分类、方向推荐和购物车。
2. 打开“课程路径”：查看基础 → 工具 → 实战 → 交付的关系，点击编号查看先修与后续课程；载入 1、2、3、5、7 天组合模板。
3. 在“我的组合”调整天数、人数、班次、预算和顺序，生成完整教案，编辑简介和宣传摘要，导出 JSON / Markdown，或打印为 PDF。
4. 在“智能组课”指定主题、对象、起点与预算，生成建议。当前使用**规则组课**；结果显示选课原因、前置条件和容量限制，点击“采用方案并编辑”后才替换当前组合。
5. “人员与组织”邀请讲师或运营；邀请链接由管理员自行交给指定邮箱的使用者，系统不会自动发送邮件。
6. “课程管理”创建或修改课程，保存草稿 → 提交审核 → 管理员审核发布。讲师只能编辑本人模块，不能审核发布。
7. 客户自行注册，在组合页“提交询价”；机构在“客户询价”起草报价，由管理员正式发送；客户在“我的询价”确认。报价记录保留每次版本。

测试数据使用独立数据库，正式本机实例不包含验收用的客户或测试报价。

## 角色与权限

| 身份 | 可操作范围 |
| --- | --- |
| 访客 | 浏览公开菜单、详情、公开附件；本地组合与导出 |
| 客户账号 | 保存个人方案、规则组课、提交询价、查看/确认自己的报价、下载已授权项目资料 |
| 讲师 | 机构后台、编辑本人模块、管理草稿附件、提交/撤回审核 |
| 运营 | 机构课程和资源管理、客户需求跟进、起草报价 |
| 管理员 | 机构成员管理、审核发布/下架课程、正式发送报价、查看操作记录 |
| 机构负责人 | 管理员全部能力，以及负责人角色调整；不能停用最后一位负责人 |
| 平台管理员 | 创建机构并指定已注册负责人；不能凭平台身份越过其他机构的数据权限 |

普通注册不会自动获得机构权限。机构停用成员后，其后台和内部资源访问立即失效。

## 课程内容、价格和版本

- 每门课程含：简短介绍、详细介绍、对象、目标、完整分段课纲及分钟数、教学活动、课堂练习、成果、评价、准备资料、课后任务、实施说明、工具、先修关系、内部宣传提示词和附件。
- 保留原 F13 的镜头施工单方法卡；讲师可在教学中使用。内部提示词不通过公开课程 API 返回。
- 默认价格 **0 元 / 模块 / 班次**。金额内部用整数“分”计算，避免小数累计误差。
- 组合参考小计 = 模块参考价之和 × 班次。人数用于班额提示，不直接乘价格。0 元模块不等于整个培训项目免费。
- 项目报价 = 需求快照中的模块小计 + 实施/差旅等明细 − 优惠。包含范围、排除范围、税费口径、有效期必须明确。
- 修改已发布课程会创建新版本草稿，公开菜单仍展示原发布版本。审核通过后才切换；旧需求、旧教案和旧报价不随课程改价而变化。
- 并发编辑采用递增修订号；过期内容不能静默覆盖新修改。方案中的旧课程版本会触发重新核对提示。
- 课纲分钟之和必须等于模块时长；禁止循环前置、跨机构前置以及公开课程依赖内部课程。
- 附件有公开、机构、项目三种范围，默认最大512MB（可通过 `MAX_UPLOAD_MB` 调整）。公开附件必须随对应版本正式发布；项目资源须由运营或管理员在课程管理页选择具体询价授权。
- 课程前置的“任一满足”与“全部满足”分别校验。组合可声明已有同等能力；规则引擎不强行把超出每日时长的模块拆开。

## 启动、停止与运行环境

需要 **Python 3.12 或更高版本**。依赖已锁定在 `requirements.txt`，本机构本机已安装虚拟环境。

Windows 从仓库目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\platform\start.ps1
powershell -ExecutionPolicy Bypass -File .\platform\stop.ps1
```

首次安装如 `python` 不在 PATH，给启动脚本传 `-Python 'Python可执行文件完整路径'`。脚本在隐藏窗口启动服务，进程号与日志写入 `platform/runtime/`。本机默认只监听 127.0.0.1，不会自动开放给局域网或互联网。电脑关机或服务停止后地址不可访问；需要再次运行启动脚本。未修改系统开机启动项。

手动运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\platform\requirements.txt
.\.venv\Scripts\python.exe .\platform\run.py
```

复制 `platform/.env.example` 为 `platform/.env` 可调整地址、数据目录和 AI 服务。修改配置后重启服务。`APP_ORIGIN` 必须与浏览器使用的协议、域名和端口一致，否则写入请求会被拒绝。

## 服务器部署（Docker Compose）

服务器部署包解压后进入 `platform/`，需要 Docker 和 Compose：

```bash
cp .env.example .env
# 编辑 .env，把 APP_ORIGIN 改成最终访问地址，例如 https://courses.example.com
docker compose up -d --build
docker compose logs --tail 50
docker compose exec course cat /data/首次登录.txt
```

持久数据位于 Docker volume `course_data`，容器更新不会清空课程。第一次启动生成随机负责人密码；仅从服务器终端读取，不会写入镜像。不要把 `.env`、登录文件、数据库和备份提交到公共仓库。

Compose 仅把端口映射到服务器 127.0.0.1。通过反向代理提供 HTTPS，例如服务器上 Caddy 的配置：

```caddyfile
courses.example.com {
    request_body {
        max_size 514MB
    }
    reverse_proxy 127.0.0.1:8765
}
```

域名解析至服务器后，将 `.env` 中 `APP_ORIGIN` 设置为 `https://courses.example.com`，然后 `docker compose up -d --force-recreate`。系统据此启用 Secure Cookie。代理应另行设置合适的连接/请求速率限制；本应用不信任客户端转发的 IP 头，避免伪造来源。

本版本为**单服务、单 SQLite 数据卷**设计，适合第一阶段机构运营。不要把 SQLite 文件放在网络共享盘或同时运行多个写入实例。大规模并发、多副本部署需迁移到集中式数据库和对象存储。当前电脑未安装 Docker，因此容器配置已随包提供，但未在本机实际构建镜像；Python 本机版已完成验收。

## 智能体与真实 AI 接入

默认规则引擎不需要 API Key：先计算主题匹配与入门顺序，再补齐依赖、检查整模块排课容量和模块预算，最后生成教学日程。选择原因、未能容纳的必选课程及费用范围均会显示。每个账号在每个机构有每日请求限额，可在机构设置调整。

真实 AI 采用兼容 Chat Completions 的接口，在 `.env` 中填写：

```dotenv
AI_BASE_URL=https://your-provider.example/v1
AI_API_KEY=请仅在服务器本地填写
AI_MODEL=服务商支持的模型名称
```

重启后生成方式出现“规则选课 + AI文案”。接口会在 base URL 后追加 `/chat/completions`。真实 AI 接收选中课程的简介、成果、时长，以及用户填写的对象和教学重点；不会上传联系方式、密码或内部提示词。AI 只生成标题、简介和宣传草稿，不能修改权限、课程选择、价格和排课。调用失败会明确显示“规则方案 · AI调用未成功”。AI 文案可以编辑并随方案保存。

当前未配置任何真实密钥，未调用或计费外部模型；真实 AI 路径通过模拟服务验证响应与失败回退，尚未与用户的实际供应商联调。

## 数据备份与恢复

Windows：

```powershell
.\.venv\Scripts\python.exe .\platform\manage.py backup
```

Docker：

```bash
docker compose exec course python manage.py backup
# 输出备份路径，再把该文件复制到受控的备份位置：
docker compose cp course:/data/backups/具体备份文件.zip ./
```

SQLite 通过专用 backup API 获取一致数据库快照，资源文件不可变，备份同时包含 `files/`。备份包含客户联系信息与机构资源，应仅授权人员保存。首次登录明文文件和 AI 配置不会加入备份。

恢复到本机：先停止服务，将备份解压到一个新的数据目录，再把 `.env` 的 `COURSE_DATA_DIR` 指向它；保留原数据目录以便回退，重启验证。恢复到服务器卷时同样先停止写入、保留原卷、恢复 `courses.sqlite3` 和 `files/`，确保 UID 10001 可以读写后启动。恢复后保留原有账号与密码。

忘记密码可由有本机/服务器管理权限的人执行交互式重置：

```powershell
.\.venv\Scripts\python.exe .\platform\manage.py reset-password --email owner@local.test
```

Docker 对应 `docker compose exec course python manage.py reset-password --email 账号邮箱`。密码不显示在输入回显或命令参数中，重置会注销该账号所有会话。

## 验证与实现

- 技术栈：FastAPI、SQLite、原生 HTML/CSS/JavaScript。应用独立于原静态页面；无需 Node 构建前端。
- 数据表包括机构、账号、成员、邀请、课程、课程版本、资源、组合方案及版本、询价快照、报价版本、项目授权、组课记录和操作日志。
- 会话为 HttpOnly Cookie，随机 token 仅存哈希，密码使用独立盐的 scrypt；服务端执行角色/机构鉴权，写入带 CSRF 检查。上传文件不直接作为脚本或 HTML 展示。
- 本机 OpenAPI 接口定义在 `/openapi.json`；接口与响应结构以代码为准。业务数据路径不通过静态文件服务开放。

运行后端测试：

```powershell
.\.venv\Scripts\python.exe -m pytest .\platform\tests -q
```

浏览器验收脚本为 `tests/browser.cjs`。需要 Node.js、Playwright、Microsoft Edge；设置 `PLAYWRIGHT_MODULE` 和可选 `TEST_PYTHON` 后运行。脚本使用 8766 端口和独立测试数据目录，不会改动正式数据库。截图和报告存放在 `test-results/`，不加入部署包。

本阶段未接入在线收款、自动邮件、验证码/邮箱验证、短信、第三方登录或真实 AI 服务。已实现的是账号登录、机构运营、课程生产审核、客户组课询价、人工报价与确认的完整闭环。


## 1.1 界面与课程资源

品牌统一为“AI微课工坊”，导航采用“课程中心 / 培训方案 / 机构管理”分组，账号设置移至右上角。移动端通过二级菜单访问各业务页面。

课程详情分为“课程概览 / 教学大纲 / 课程资料”，以学习目标、实践任务、成果与评价组织内容。课程资料预留课件、录播及配套资料，尚未发布或当前账号无权访问时显示空状态，不提供无效的播放入口。

- PPT/PPTX 支持上传和下载；需要在线展示时，可同时上传 PDF 版本。不依赖第三方在线 Office 服务，也不会向外部服务发送机构课件。
- PDF 支持站内预览及下载。
- MP4/WebM 支持原生播放器、进度拖动和下载，预览接口检查与下载接口相同的课程版本、机构和项目权限。视频能否解码取决于浏览器，建议使用常见的 H.264/AAC MP4 或 VP8/VP9 WebM。
- 单文件默认512MB，服务器采用分段读取写入，不将完整录播载入内存；代理上传限制需高于应用限制（示例514MB）。

首屏信息组织参考 [Coursera for Business](https://www.coursera.org/business) 与 [Udacity for Business](https://www.udacity.com/enterprise/overview)，以培训领域、能力目标、课程范围及行动入口为主；未使用第三方品牌、业绩或合作方背书。


## 1.2.1 培训主题与机构

顶部“培训主题”是课程体系入口，目前为“AIGC视频创作学院”。主题名称和稳定标识独立保存在 `web/training-themes.json`，不再读取机构名称。当前仅开放视频创作体系；后续上线“办公AI学院”时，需要同时加入该主题的课程归类、筛选及组课规则，不能只添加下拉选项。
